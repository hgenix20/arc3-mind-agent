## Gaps in learning and intelligence

Ranked by score impact. Each entry: evidence, spec section, one proposed change.

1. **Harm never reaches the veto band, so the same death repeats.** tu93: 68 deaths on one kind, harm p stuck at 0.05 to 0.14 (low band, no veto, no perseverance check), 42 of the deaths inside planner segments, a death every 4 moves in L3 and L5. Run-wide 124 deaths, 45 inside planner segments. Spec 3.9, 4.10a, 4.10b. Change: count an adverse trial only when the simulator predicts contact with the kind on that move, and after 2 deaths on the same (label, kind) key set the key to the certain band for the rest of the level instance.

2. **Stale fallback counter after an explorer win locks the mind out of every later level.** lp85 L1 to L5, ft09 L1, bp35 L1, s5i5 L1, lf52 L2, m0r0 L2: each started at fallbacks_in_row 26 or more, got 25 fallback moves and 0 planner calls, then went back to the explorer. 10 level instances, 250 moves, 0 planner calls. Spec 3.11 (controller), 4.13 (hybrid). Change: `resume()` runs `_end_instance()` and raises the "level start" wake; add a test that the first move after an explorer-won level has fallbacks_in_row 0 and a planner call.

3. **A planner timeout at level start costs the whole level.** Call 0 timed out in 9 games (8 of them the cold concurrent start), no retry, and fallback moves never wake the planner (1,781 of 1,861 fallback moves had no call). cn04 and ft09 finished with 0 successful calls; cn04 won 0 of 6. Spec 4.9f, 3.12. Change: retry a failed call once with a longer read timeout, and make 5 fallback moves in a row a wake reason; stagger the first call of each worker by a few seconds.

4. **Segments break before they start.** 208 of 1,077 planner segments rejected at step 0; 65% of search segments and 36% of planner segments broke; 499 of the mind's wakes were "segment broke, return to fork". Winning and breaking segments had the same p_path (0.07 to 0.12). Spec 3.5, 4.9e, 4.4c. Change: simulate the whole segment before storing it and drop any segment whose first step the simulator rejects; ask the planner once more with the rejected step named (the spec's 3.5 "once" path is not visible in the logs).

5. **The fork tree never pays.** 81 forks, 156 failed branches (98 "no known route to the fork"), 26 return routes of which 23 had length 0 or 1, 605 of 610 replans from the root, 0 level wins after a return route. Spec 3.6, 4.7c. Change: store the executed move list to the fork at fork_open (the spec's "moves that got there") and use it as the return route instead of searching known moves; until that works, skip the fork step and replan from the root directly (it saves the branch_failed and return_route calls).

6. **Perseverance allows everything when no goal path exists.** sc25: 142 perseverance events, 94 "no other way", 153 harm events in 450 moves; wa30: 84 and 42 in 150 moves. "No other way" is true whenever the hypothesis list has no goal-reaching path, which was the standing state in both games. Spec 4.10c, 3.4. Change: Reason A applies only when some hypothesis reaches the goal through the move; with no goal path at all, a medium-band move is refused and the move goes to curiosity instead.

7. **Planner time is the run's budget.** 11.0 s per call, 42% of all game seconds, 85% in sp80 and 82% in tr87; two games stopped on the deadline; prompts average 4,417 tokens. tu93 alone ran 3,328 s. Spec 4.10d, 4.9a. Change: cut the briefing to the fixed lists with hard per-list limits (the scene list is the bulk; unverified), cap completion at 300 tokens, and make the move gate trip at 15 s so a slow call costs a fallback instead of the deadline.

8. **p_step and p_path are too small to rank anything.** Observed match rate is 0.10 to 0.20 above the predicted bin everywhere below 0.7; 39% of moves predicted under 0.1 and matched 20% of the time; median p_path 0.04. Spec 4.4c, 4.7b. Change: replace the 0.5 prior per unknown step with the run's own observed match rate for the "no rule" case (0.20 at present) and apply a per-bin correction from the calibration table at the start of each game.

9. **Long-term memory stores no-ops and one game fills it.** 50 rules, 39 "does nothing", 32 from tu93, 1 rule seen in two games, lessons present in 881 briefings and never referenced; 0 rules promoted at 3 of the 6 level wins. Spec 4.12b, 4.12c. Change: promote to long scope only rules with an effect other than `none` (keep no-ops in working memory), and key lessons by role words (mover, harm, blocker) in place of kind hashes so a second game can match them.

10. **The planner's skill and fact outputs are thrown away.** 619 skill requests, 605 dropped because a segment was also given; 277 facts dropped for schema reasons (184 missing object); the model repeats the previous reply's text and proposes one action twelve times. Spec 4.9d, 4.9a, 4.9c. Change: make the reply either a skill or a segment (reject replies with both, re-ask once), and put the fact schema with one valid example in the briefing; log the skill that ran so the 13 runs can be compared with the 605 drops.

11. **Curiosity tests spend the level without a plan.** sb26 121 learn moves of 150, 0 wins; r11l 103 of 174; vc33 L1 40 moves against human 7 with 28 learn and fallback moves. Spec 4.11, 3.10. Change: cap learn moves at 20 per level instance before the first planner segment, and count a test that changed nothing twice as a veto reason for that label on that kind.

12. **Only 2 of 6 wins came from a plan.** The other four were a curiosity test (r11l, tn36), the goal heuristic (lf52) and fallback (vc33). The planner's one winning segment (ls20) was 1 step long. Spec 3.2, 4.7a. Change: after a level win, write the winning move's hypothesis and segment to the completion record so the next level starts from a plan shaped like the one that worked (the completions store holds only move counts now).
