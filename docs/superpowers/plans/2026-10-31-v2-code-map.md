## 2. Decision order (module docstring, lines 6-101)

1. `GAME_OVER` frame: learn the death (`game_over=True`), log `game_over`, reset tracker and noise tracks (keep counter cells), clear plan, return RESET (branch `reset`). `NOT_PLAYED` returns RESET and learns nothing. The frame after a RESET learns nothing.
2. `levels_completed` rose: `level_up` fact, `goals.level_up`, log `level_up`, reset, `fluid_sleep` over the level's used fact keys, `mem.new_level()`, Transfer `carry`, clear plan/history/tried/frontier.
3. Else: tracker (last prediction's scene as prior), kinds, modes, noise; strip noisy things; `learn` + `check` the previous prediction; if the pursued goal holds with no level-up, set it `probing` and start a commit probe (branch `commit`); `goals.note_reached`.
4. A plan stops only on `plan_breaks`. Steps left: branch `follow`. A broken plan whose goal does not hold is a failed attempt; `STALL_AFTER` failures stall the goal.
5. Exactly one action survives the plan vetoes: branch `forced`. Else `goals.propose` + `search`: executive-named goals alone, then confirmed forms not stalled, then all open goals (branch `plan`, why `goal <id>`). Sequence steps rank first; a step that already holds gets a bump (why `sequence bump <id>`).
6. `budget_tight` partial step; sequence click (`sequence step`/`sequence try`); Voi test (branch `learn`) while `_tests_attempt < MAX_TESTS_PER_ATTEMPT`.
7. Best partial plan (why `toward <id>`) only if it ends closer than any real frame this life; else novelty (why `explore novel`, no plan kept).
8. B0 with vetoed candidates excluded (branch `fallback`).
9. Veto runs on every option; B0 is never vetoed. The chosen action's prediction is kept for step 3 of the next call.

Past the deadline: no search, tests or vetoes; follow the plan or B0 (line 118). Executive turn rules: lines 120-164. Failure guard: lines 166-170.

## 6. How an LLM plan runs

1. `_apply` (1640-1645): `_llm_plan = list(reply.plan)`, `_llm_test = None`, `_llm_protect = ∪ goal_sigs(g, scene)` over `reply.goals` (empty when none named), `_llm_scene = scene`. A test-only reply sets `_llm_test` instead.
2. The same move: `_llm_choice(scene, late)` (1478). A pending test is consumed first (dropped without a move when late; if vetoed, the plan is tried in the same call). Then `_llm_follow` (1490): `pop(0)`, `_remap` (click follows sig; gone → `veto` "click target gone"), `_offer(..., "plan", "llm plan", late, plan=True)`; a `_PLAN_VETOES` refusal empties `_llm_plan` (and `_plan`) and notes `plan blocked`.
3. `_choose` (985-989): `_llm_step=True`, `_plan_goal=None`, `predict(scene, action, mem, assume_still=mover_sigs | _llm_protect)`. A prediction with no scene is still taken.
4. Next frame, `_check_plan` (925-932): `plan_breaks(..., unknown_ok=True)` → `_llm_plan=[]`, note `miss that matters`; an exhausted plan notes `plan finished`.
5. Stops: a miss that matters; a refused or unmappable step; exhaustion; any `_restart` (game over, NOT_PLAYED, level up, `resume`, `agent_error`), which clears `_llm_plan/_llm_test/_llm_step` (607, 667); a later reply with a plan or test replaces it. While steps remain, `_wake_reason` holds (branch `plan`), so no turn interrupts it. Past the deadline, steps run with vetoes skipped.

### `Fact` (slots, mutable, 141–179)

## 5. Probability: what exists against what spec 4.x needs

**Per fact.** Spec M4.4 (line 543) wants `p = (confirmations + 1) / (confirmations + contradictions + 2)`, four decimals, bands at 0.8 and 0.3. From a `Fact`, `confirmations = hits` and `contradictions = misses` give a lifetime estimate, except that `hits` resets to 1 on re-seed while `misses` never resets, so a re-seeded fact is under-rated. For "since the last refinement" (M4.4b, line 552) the code has `hits` (since seed) and `streak` (consecutive misses now) and nothing for misses since seed. No `probability` field or property exists; `Fact` uses `slots=True` (141), so one cannot be attached ad hoc: add a field, or compute in a wrapper. `_borrow` ranks by `-hits` (408), not probability (spec 4.3, line 497).

**Per step.** `Prediction.sources` names the fact per thing, `used` the deduped set, `lent` the borrowed ones, `assumed` the pairs with no fact (spec M4.4c rule 5, line 564: factor 0.5, path marked uncertain). A step probability is computable outside the predictor over `{mem.facts[k] for k in pred.used if k in mem.facts}` (the blocked placeholder key may be absent). `used` is deduplicated, which matches rule 4 (line 563). Nothing applies "the rule with the highest probability" (M4.8a step 2, line 792): `lookup` order is fixed by specificity.

**Rule record (spec 4.2, lines 435–448)** against `Fact`: present are `key`, `effect` (`effects`), `created_level` (`level`), `confirmations`/`contradictions` (`hits`/`misses`, with the reset caveat), a three-way threshold status (not hypothesis/fact/retired), `statement` (`line()`), and a partial `source` (`CLAIM_MOVE` in `evidence` marks a claim; all else is observed). Absent: `id`, record `kind`, `conditions` (the context string is the only condition), `probability`, `scope`, `created_game`, `last_revised`, `harm`. The **canonical key** (line 449) must not carry the color; today every subject does (`c<color>:<shape>` or `kc<color>:<shape>`) and labels are action ids, not roles. The color-free hooks are `Thing.shape`, `_shape_of_subject` (210–213), the `_siblings` index keyed by shape (251), and `kinds.base_sig`.

**Logs (spec 4.2 line 486; 4.13 lines 1116–1126).** None here. `record` returns `"new" | "hit" | "miss"` and `learn` returns the touched keys, so a wrapper around `FactMemory.record`, `revise` and `delete` can emit create/confirm/contradict/retire events; `mem.missed` lists the keys that missed since `new_level`.

**Stores (spec 4.2 table, lines 456–461).** `FactMemory` is one in-memory working store: `new_level` keeps facts, `forget` drops them, there is no death-specific path, no file I/O, no long-term scope.

**Harm (spec 4.10a–b, lines 955–972).** Death knowledge is the `("any", sig, "touch:<c>" | "near:<c>")` facts with `Effect("game_over")`, the `safe_touch`/`safe_near` sets, and `Prediction.game_over` as a bool. No health value, counter, or harm kind exists in these files.

**Movers of their own (M4.8b, line 804).** `learn` keys every observation on the action sent; there is no "no action" label and no time axis. **Continuous movement (M4.8c, 811–817)**: `Change.dx/dy` per thing reach `learn`; `_record_move` only converts to slide or teleport and flags nothing.

**Frontier pairs (M4.11a, line 1021).** `Prediction.unknown` and `assumed` give `(label, subject)` pairs; `tester.py` already reads `pred.lent` and `pred.used`.

### `Goal` (frozen, slots, :75)

| kind | value | None when |
|---|---|---|

| clear | things of color left + (`kin.mover` set, ≤20 left, mover not that color) cells of `route()` through them with Manhattan legs | never |

| match | mismatched cells | no grid, off board, unequal sizes |

## 8. budget.py and counter recognition

`Counter(color: int, axis: Literal["row","col"], lines: frozenset[int], shrinks: bool)` (:41). `BUDGET_DEATH_MOVES = 2`, `MIN_DRAIN = 6`, `MIN_FIT = 5`.

`BudgetReader` (:84): `counter` property; `set_counter(counter)`; `new_level()` (re-init); `start_life(grid)`; `observe(grid, *, changed=True)`; `chosen() -> "all"|"busy"`; `moves(count=None) -> int`; `remaining() -> int|None`; `per_life() -> int|None`; `game_over()`. Cells = band cells equal to the color. Two least-squares fits of cells against moves (`all` every move, `busy` moves that changed the screen or the bar); the lower misfit wins once both have 5 points. Rate = ∓slope, None until ≥6 cells drained; after a game over with < 2 moves' worth of bar left, rate = starting bar / that life's moves. `remaining = round(left / rate)`, left = cells (shrinks) or band free cells (grows).

Recognition lives in `noise.py` (:29-35, :159-170): a track is a counter when its size changed `COUNTER_STEPS = 3` times, all in one direction (`min(grew, shrank) == 0` at flag time), and on each change it was a strip < `COUNTER_THIN = 2` cells across within `COUNTER_EDGE = 2` cells of the board edge. `_note_counter` (:143) sets axis by the wider dimension and `shrinks = shrank > grew`. fluid.py picks the first shrinking counter, else the first (:1162-1164).

Health bar versus move counter: nothing in the code distinguishes them. Every `Counter` is read as a move budget; no record links a drop to a contact or an action, `observe` only receives `changed: bool`. A bar that falls on hits would fit the `busy` count or neither and yield a wrong `remaining`. Inferred: a bar that also rises (healing) is never flagged, since flagging needs strict monotony.

Each line is `_clip`ped to its width. Final cap is a hard character cut `text[:cap]` (`turn.py:247`), 6000 or 9000. Note: `FluidAgent._moves` is `deque(maxlen=MOVE_LOG_LINES)` (`fluid.py:574`), so a drive turn never actually gets more than 8 move lines.

Object line (`turn.py:183-188`): `#{id} c{color} {w}x{h} at ({x},{y})`. `_available` (`turn.py:210-219`): `A<n>` for every id except 0 and 6, plus `click #<id>` when 6 is available, else `none`.

Helpers reusable by any briefing builder: `_clip(s, width)`, `_block(title, lines)`, `name_sigs(text, scene)` (replaces every `c\d+:[0-9a-f]{10}` sig with `#id` lists, max 4 then `+N`, or `(off screen)`), `render_fact(fact, scene, owner=None)` (`A3 #2 any: moves 1 cell left [solid 6/0]`; click labels `A6:<sig>@<ring>` become `click on #ids`).

**`build_messages(inp) -> list[VMessage]`** (`turn.py:250-266`): `[{"role":"system", "content": DRIVE_SYSTEM_PROMPT if inp.drive else SYSTEM_PROMPT}, {"role":"user", "content": [text part, image_url(png(grid)), image_url(diff_png(prev_grid, grid)) if prev_grid is not None]}]`. Images are always sent; there is no text-only switch.

**`take_turn(chat, inp, *, seed) -> Reply`** (`turn.py:269-277`): `chat(build_messages(inp), seed)` then `parse_reply(completion.text, inp.scene, inp.available)`. `ImagesRejected` propagates; any other exception becomes `Reply(dropped=("turn failed: <Type>: <msg>",))`. No time limit here.

## 2. The reply contract: `contract.py`

Constants (`contract.py:46-56`): `MAX_PLAN_STEPS = 8`, `MAX_FACTS = 24`, `MAX_MODEL_CHARS = 1500`, `MAX_RULE_CHARS = 4000`, `_MAX_TEXT = 300`. Regexes: `_ACTION_RE = ^A([1-7])$` (matched on `name.upper()`), `_CLICK_RE = ^click\s*#\s*(\d{1,6})$` (IGNORECASE), `_INT_RE = ^#?\s*(-?\d{1,6})$`, `_COLOR_RE = ^c?(\d{1,2})$`.

Types:
- `PlanItem(action: Action, expect: str)` (`:60-64`); for a test, `expect` holds the question.
- `FactClaim(label: str, subject: str, effects: tuple[Effect, ...])` (`:68-73`); `subject` is a sig or `"any"`, `label` is `facts.action_label(act, scene)`.
- `Reply(goals=(), plan=(), test=None, notes="", dropped=(), claims=(), model="", rule="")` (`:77-87`).

**`parse_reply(text, scene, available: Sequence[int]) -> Reply`** (`:222-227`) never raises. Rules in `_parse` (`:344-371`):
1. First JSON object found by `json.JSONDecoder.raw_decode` scanning each `{` (`:90-101`); none gives `dropped=("no JSON object in reply",)`.
2. **Valid action string** (`_action`, `:186-203`): `A1`..`A7` where `n in available` and `n != 6` (`A6` is rejected with "A6 is a click: write click #<id>"); or `click #<id>` where `6 in available` and `id` is a thing id in `scene.things`. Anything else: "unknown action: ...".
3. **Click to cell**: `x, y = objects.click_cell(t)` (cell nearest the thing's centroid, ties by smallest cell, `objects.py:543-548`) and `Action(6, x, y)`.
4. `goals`: `reach`/`cover` (`a`, `b` ids on screen, distinct, mapped to sigs), `clear` (color 0..15), `count` (color, `n >= 0`), `match` (two `[x0,y0,x1,y1]` regions, `0 <= x0 < x1 <= 64`). Duplicates deduped.
5. `plan`: up to 8 steps; invalid steps dropped with a reason; a 9th step adds "plan capped at 8 steps".
6. `test`: parsed with `_step`; **kept only when the plan is empty** ("test dropped: the plan wins", `:357-358`).
7. `facts`: first 24 items; `object` is `"any"` or an on-screen id; effects normalized (`no change`/`blocked`/`nothing` → `none`; `disappears`/`vanish`/`removed` → `disappear`); `move` needs integer `dx, dy` not both 0 and a real object ("a move names its object").
8. `model` cut to 1500 chars, `rule` to 4000; `notes` to 300. Unknown keys are ignored (`:30`), so a new key such as `skill` needs new code in `_parse`.
9. Leniency: a lone object counts as a one-item list; ints may be `"3"` or `"#3"`; colors may be `"c11"`.

## 5. Running model code: `toolbox.py`, `_tool_worker.py`, `sandbox.py`

**The DRIVE rule runs in `ToolWorker`, not in `ProgramSandbox`.** `ToolWorker` (`toolbox.py:212-312`) spawns `python -u _tool_worker.py` (no `-I`, stderr to DEVNULL), JSON lines over stdin/stdout, arguments and results as base64 pickles. `run_rule(source, objects, action, timeout_s) -> (ok, result)`; `_request` holds a lock, tags a `rid`, waits `timeout_s` (+30 s `SPAWN_TIMEOUT_S` on first use); on timeout or death it kills the process, counts `restarts`, and returns `(False, "timeout" | "crash" | "worker died")`. In the worker (`_tool_worker.py:49-57`) the rule source is `exec`'d into an empty namespace with **full builtins and unrestricted imports** (the file sets no allowlist, memory cap, or recursion limit), `ns["rule"]` is called, one rule cached at a time, exceptions return `{"ok": false, "error": ...}` cut to 2000 chars, and `sys.stdout` is pointed at stderr so prints can't corrupt replies (`:74`). Effective limits on a rule: 4000 source chars (`contract.MAX_RULE_CHARS`), 2.0 s wall per call (`RULE_S`), discard after one failure, return must be a list.

`call_tool(name, worker, *args, box=TOOLBOX, timeout_s=5.0, **kwargs) -> (result, version, error)` (`toolbox.py:315-333`): runs the newest adopted version of `TOOLS[name]` (`"search"` → `arcagent.mind.search.search`, `"route"` → `arcagent.mind.route.route`, `:105-108`) in the worker when one is adopted and a worker exists, validates the type with `spec.valid`, and falls back to the in-process original on any failure (version 0). `Toolbox` (`:127-186`) keeps versions, up to `MAX_CASES = 8` regression cases per tool, history, with `adopt(..., base=)`, `rollback(..., failed=)`. `SceneActions(simple, can_click, offsets)` (`:336-359`) is the picklable action generator for search.

**`ProgramSandbox`** (`sandbox.py:109-446`) is the other, separate runner: `python -I _worker.py PLANNER_PATH` with a reduced env, programs `step(grid, action, x, y)` and optional `goal(grid)`, ops `load/unload/predict_many/predict/predict_grid/goal/score/plan`, defaults `timeout_s=5.0`, `plan_timeout_s=30.0`, `PLAN_LIMIT_FRACTION = 0.8`, `SCORE_CHUNK = 200`, culprit blame and `dropped[pid] = "timeout"|"crash"|"reload_error"`, `ProgramSandbox.dead()` stand-in, RLock for two threads. Its worker (`_worker.py`) applies `safe_builtins()` (`:68-72`), `ALLOWED_MODULES = {math, itertools, collections, functools, heapq, copy, re}` (`:41-43`), and `RLIMIT_AS` 2 GiB on Linux (`:40`, `:288`). It has no op for `rule(objects, action)`.

**BFS to an earlier state (recipe from the code).** `path_to_frontier` cannot target a given state (its goal test is "has untried moves" and it skips `start`; `wanted` only filters moves). Write the same loop with a different goal: `prev = {start: None}; queue = deque([start])`; pop `key`; if `key == target` walk `prev` back and reverse; else for `akey, nxt in graph.edges.get(key, {}).items()` push unseen `nxt` with `prev[nxt] = (key, Action(*akey))`. ### 8. What breaks on new fields

- **facts.py.** `Fact(key, effects, evidence, hits=)` is built positionally (test_turn.py:233-239); `Effect("move", 1, 0)` positionally (test_game_model.py:33-104, test_contract.py:150, 192, 205). A field inserted before `evidence` or before `dx` breaks those; appended with a default it does not. Any new `Effect` or `Fact` field that `learn`/`record` populates and that takes part in `__eq__` breaks every `fact.effects == (Effect(...),)` assertion (test_facts.py:79, 460, 471; test_game_model.py:52, 102) unless declared `compare=False`. Pinned text: `line()` → `"A3 c1:ab12.. any: moves 1 cell left [solid 6/0]"` (test_facts.py:92, test_turn.py:234-240); status strings `thin/solid/broken` with `THIN_BELOW = 5`, `BROKEN_MISSES = 2` (facts.py:63-64; test_facts.py:61-80); `FactKey` as a 3-tuple `(label, subject, context)`, also in logged list form `["event","level_up","any"]` (test_fluid_agent.py:118, 124). `game_end.facts` is a Counter of statuses (155).
- **TurnInput** (`turn.py:112-129`, 12 required + `movers, changed, model, drive` defaulted). Built by keyword in test_turn.py:76-89 and fluid.py:1603-1616; a required new field breaks both, a defaulted one breaks nothing. Anything new rendered into the prompt must fit `MAX_PROMPT_CHARS` with 100 facts of 500 chars (118-127).
